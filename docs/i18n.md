# 多语言资源管线

app 的用户可见文案分两份存放，互不覆盖：

| 文件 | 来源 | 说明 |
|---|---|---|
| `res/values/strings.xml` + `values-en/strings.xml` | 手写 | 中文为默认语言；两文件键集必须一致（`app_name` 除外） |
| `res/values*/strings_generated.xml` | `tools/gen-strings.mjs` 生成 | **不要手改** |

## 生成

仓库内已提交生成产物 `strings_generated.xml`，日常构建与文案修改（手写部分）无需重新生成；若需重建生成文件，运行：

```bash
node tools/gen-strings.mjs <locale 目录> app/src/main/res
```

输入为两语言对照的 locale 源 JSON（`zh-Hans.json` / `en.json`，结构 `{namespace: {key: "文案"}}`），属外部输入、不在仓库内。

- 只转换 `ACTIVE_NS` 中声明的活 namespace；键名按 `{namespace}_{key 路径}` 扁平化
- 插值语法 `{name}` 转为 Android 位置参数 `%<i>$s`（索引按英文文本出现顺序；两语言插值名集合必须一致，否则报错退出）
- 断言：两语言扁平键集合完全一致

### OVERRIDES

生成时对特定键做覆盖改写（用于修正源文案在当前实现下不成立的情况），声明在脚本头部 `OVERRIDES` 表。

### DROP_KEYS

两语言都存在的键默认不触发孤儿断言；确要废弃的键必须显式加入 `DROP_KEYS`（附理由），生成时从产物中剔除。

## 校验

```bash
node tools/check-strings.mjs
```

四断言：

1. 手写双语键集一致（`app_name` 白名单）
2. 无重复键
3. 手写文件与生成文件不撞键（重复资源会导致编译失败）
4. Kotlin 源码无 CJK 字面量残留（注释剔除状态机处理 `//` 与 `/* */`）
